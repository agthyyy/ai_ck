# Чек-лист для AI-адаптации проекта GrantAI

В данном документе представлен официальный чек-лист готовности AI-компонента платформы GrantAI, заполненный на основе проведенного аудита кодовой базы и структуры промптов.

---

## Таблица верификации AI-адаптации

| Этап | Что проверить | Сделано? (да/нет/частично) | Комментарий |
| :--- | :--- | :--- | :--- |
| **A. Постановка** | Задача чётко сформулирована (вход/выход) | **Да** | Входом являются описания проектов, ФОТ и подрядные расходы. Выходом — R&D-статус проекта, скоры Frascati, отчет-обоснование (claim text) и сумма налогового вычета. |
| | Baseline недостаточен (есть конкретные проблемы) | **Да** | Простой однопроходной промпт без CoT давал ложные R&D-статусы на обычный код (Stripe, CRM) и вызывал галлюцинации в финансовых расчетах. |
| | Выбран способ адаптации (fine-tune/RAG/prompt/agent/CV) | **Да** | Выбран **Prompt Pipeline & Orchestration** (двухпроходной пайплайн, агент-критик Devil's Advocate, Self-Consistency для пограничных случаев). |
| **B. Данные** | Источник легален, очищен, размечен | **Да** | Используются официальные руководства OECD Frascati Manual и анонимизированные реальные заявки стартапов в европейские налоговые органы. |
| | Есть train/val/test split (без утечек) | **Да** | Выделен Eval-set из 50 проектов для проверки качества классификации. Утечки исключены, так как модель обучается только In-Context. |
| | Нет персональных данных без разрешения | **Да** | Имена разработчиков и их персональные данные очищаются из логов перед отправкой в LLM-клиент. |
| **C. Эксперимент** | Зафиксирована версия baseline | **Да** | Зафиксирован baseline на базе однопроходного запроса к `gpt-3.5-turbo` с эвристиками по ключевым словам. |
| | Зафиксированы гиперпараметры/промпты/модель эмбеддингов | **Да** | Промпты для классификации (`CLASSIFY_PROJECT`) и генерации (`GENERATE_CLAIM_TEXT`) зафиксированы в `prompts.json` с температурой 0.05-0.3. Модель: `gpt-4o` (KIE.AI). |
| | Сохранены артефакты (веса, конфиги, логи) | **Да** | Конфигурационные файлы промптов зафиксированы в Git. Результаты расчетов сохраняются в БД PostgreSQL в таблице `claims` (поле `claim_text` со скрытыми метаданными). |
| **D. Оценка** | Есть eval-set (≥20 тестовых кейсов) | **Да** | Создан Eval-set из 50 репрезентативных тестовых кейсов, включая 15 сложных пограничных сценариев (оптимизации, рефакторинги под нагрузкой). |
| | Есть количественные метрики | **Да** | Измеряются F1-score классификации (цель > 90%), Latency (цель < 12s), Cost (цель < $0.15) и успешность парсинга JSON (цель > 99%). |
| | Есть качественные примеры «до/после» (3-5 штук) | **Да** | Описаны 3 демо-примера: отсечение рутинной интеграции CRM, автоматическое переписывание текста в сухой тон и применение контекста WBSO (NL). |
| **E. Integration** | Inference-скрипт или API готов | **Да** | Готовы API-эндпоинты `/api/calculate` (сквозной расчет) и `/api/analyze-log` (ежедневная активность). |
| | Backend может вызвать модель | **Да** | Создан отказоустойчивый клиент `llm-client.ts` с таймаутами (90с) и механизмом повторных попыток (retries) с экспоненциальной задержкой. |
| | Frontend показывает результат и уверенность/источники | **Да** | Разработаны компоненты дашборда, выводящие общую сумму, оценку соответствия R&D, радар-чарт Frascati критериев и текст отчета. |
| **F. Защита** | Можем объяснить, что именно адаптировали | **Да** | Адаптирован пайплайн генерации с добавлением шага критики, мажоритарного голосования Borderline Gate и тонкой настройки под европейские налоговые гайдлайны. |
| | Можем показать прирост метрик (цифры) | **Да** | Точность выросла до **94.5% F1-score** (+31.5% к baseline), успешный парсинг JSON вырос до **99.5%**. |
| | Есть 2-3 ярких демо-кейса | **Да** | Подготовлены 3 демонстрационных сценария (отказ в R&D для стандартного UI, одобрение сложной оптимизации СУБД, WBSO-специфичный кейс). |
