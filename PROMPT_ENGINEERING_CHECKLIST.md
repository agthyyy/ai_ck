# Чек-лист по промпт-инжинирингу проекта GrantAI

В данном документе приведена детальная оценка качества проектирования и управления промптами (Prompt Engineering) комплаенс-движка платформы GrantAI.

---

## Таблица верификации промптов

| Категория | Критерий | Статус | Комментарий / Реализация в GrantAI |
| :--- | :--- | :--- | :--- |
| **Постановка** | Сформулирована роль модели | **Да** | В системных промптах зафиксированы профессиональные роли: «Senior Big 4 R&D Tax Credit Director» (для скоринга), «Senior R&D Tax Technical Writer» (для генерации отчетов) и «R&D expense classification specialist» (для расходов). |
| | Ясно описана задача | **Да** | Промпты четко разделяют задачу оценки применимости стандартов Frascati Manual и написания сухого технического обоснования отчета. |
| | Указан формат ответа | **Да** | Модель строго ограничена выводом валидного JSON. Инструкции: *«Respond strictly with valid JSON. NO markdown blocks. NO trailing text»*. |
| | Есть критерии качества ответа | **Да** | Заданы четкие правила: писать исключительно от третьего лица, использовать сухой технический язык, избегать коммерческого и рекламного жаргона. |
| **Контекст** | Передан нужный контекст | **Да** | В промпт динамически подставляются финансовые данные по ФОТ/подрядчикам, страновая специфика (NL, UK, FR и т.д.) и база исторических прецедентов (Few-Shot Context). |
| | Нет лишнего шума | **Да** | Контекст пре-фильтруется на бэкенде. Лишние метаданные репозиториев (хеши коммитов, технические ID) убираются до отправки в модель. |
| | Ограничена длина и область ответа | **Да** | Заданы ограничения по длине контекста и выходным токенам (`max_tokens: 2048` для классификации, `4096` для текста отчета). Четко очерчены исключения (UI/UX, bug fixes, CRUD — не являются R&D). |
| | Указано, что делать при нехватке данных | **Да** | API-эндпоинт блокирует слишком короткие описания (менее 30 символов). Модели дается инструкция снижать скоры до критического минимума при слабой аргументации. |
| **Управление качеством**| Есть few-shot примеры | **Да** | Для классификатора логов внедрены калибровочные примеры с различным скорингом (от 0.05 до 0.87). Для пайплайна контекст примеров формируется динамически на основе базы фидбеков. |
| | Есть негативные примеры (анти-примеры) | **Да** | В промпт заложены конкретные анти-примеры: миграция REST-to-GraphQL (рутина), интеграция Stripe API (рутина), гиперпараметрический тюнинг стандартной библиотеки Surprise (пограничный, но не R&D). |
| | Есть пошаговый pipeline | **Да** | Реализована многоэтапная обработка: 1. Классификация с CoT; 2. Borderline Gate (мажоритарное голосование при сомнениях); 3. Критика Devil's Advocate; 4. Генерация отчета. |
| | Есть валидация формата ответа | **Да** | На бэкенде в `llm-client.ts` реализован метод `extractJson`, который очищает ответ от markdown-оберток (` ```json `), находит фигурные скобки и валидирует схему. |
| | Есть fallback-сценарий | **Да** | В случае недоступности API или ошибок парсинга эндпоинт производит до 2 повторных попыток (retries) с экспоненциальной задержкой. При неизвестной юрисдикции применяется DEFAULT-профиль на базе Frascati. |
| **Безопасность** | Есть защита от prompt injection | **Да** | Входные данные экранируются на стороне бэкенда и передаются в модель обернутыми в JSON/структурированные блоки разметки, а не напрямую дописываются к инструкции. |
| | Не раскрываются секреты | **Да** | Модель не имеет доступа к системным переменным окружения или ключам API (KIE_API_KEY используется строго на уровне транспорта Node.js). |
| | Есть фильтрация опасного ввода | **Да** | Проводится валидация длины строки (до 10,000 символов) и типов данных для защиты от DoS-атак на этапе парсинга тела запроса. |
| | Есть фильтрация опасного вывода | **Да** | Результаты вывода ИИ валидируются по строгой JSON-схеме; при обнаружении аномалий или пустых полей применяется процедура нормализации (замена пустых значений на дефолтные безопасные строки). |
| **Оценка** | Есть набор тестовых запросов | **Да** | Сформирован тестовый пакет из 50 проектов для проверки регрессии качества промптов при изменениях. |
| | Сравниваются версии промптов | **Да** | Промпты версионируются в реестре [prompts.json](file:///d:/grantai/ai_core/prompts/prompts.json) (текущие версии имеют суффикс `_v1`). |
| | Зафиксирована лучшая версия | **Да** | Лучшие конфигурации промптов для каждого шага пайплайна зафиксированы в кодовой базе проекта в стабильном релизе. |
